# 社区药箱 · 过期药回收与分类交接系统

社区回收点收取居民过期药后，完成 **核对预约 → 差异居民确认 → 按类别封袋 → 保管交接 →
处置单位签收** 的全流程记录与追溯。扫码与通知均在**本地模拟**，不依赖任何外部服务。

技术栈：**Java 17 + Quarkus 3.15（RESTEasy Reactive）+ Hibernate ORM 6 + SQLite**，
前端 **Svelte 4 + Vite**，构建产物直接由 Quarkus 作为静态资源提供，单端口 `8080`。

---

## 一条命令启动

```bash
./run.sh          # 首次会自动构建 Svelte 前端，然后在 http://localhost:8080 启动
./run.sh test     # 运行交付前验证测试（12 个用例，覆盖全部硬性规则）
```

> 脚本会自动使用系统的 JDK17/Maven，或 `~/tools` 下的本地 JDK/Maven；前端仅在首次启动
> （或设置 `REBUILD_WEB=1`）时用 npm 构建。SQLite 数据库文件为项目根目录的 `medreturn.db`，
> **重启后数据保留**。

浏览器打开 <http://localhost:8080>，页面分四个工作台：

1. **收件核对 · 分类封袋**
2. **封袋管理 · 袋号追溯**
3. **保管交接 · 处置签收**
4. **居民凭证查询**

## 业务规则（均由后端强制，前端仅引导）

### 1. 核对预约与实收，差异需居民确认
- 现场逐条登记实收数量；保存后若与预约数量不一致，预约进入「待居民确认」。
- 差异**未经居民确认不能封袋**（接口返回 `409`）。

### 2. 按类别封袋；危险/冷藏突出文字要求
- 一袋只能装**同一类别**；袋号全局唯一，关联类别、数量、封袋交接人、保管位置。
- **危险药品**：必须双人核对（操作人 + 另一名复核人）、专柜加锁、袋身文字标识。
- **冷藏药品**：封袋必须记录 **2–8℃** 温度，存入 `COLD-` 冷链库位。
- 现场页面顶部与相关药品行均以 **▲ 危险药品 / ❄ 需冷藏 2-8℃ 文字 + 符号** 提示，
  颜色仅作辅助，**不仅用颜色表示**（接口也返回 `dangerous` / `cold` / `handlingTip` 文字）。

### 3. 封袋后内容冻结，拆袋必须双人复核留痕
- `SEALED` / `SIGNED_OFF` 状态下任何追加、修改一律 **`409` 拒绝**。
- 确需拆袋：必须填写**两名不同**工作人员（操作人 + 复核人）与原因，
  记录 `OPEN` 操作；拆袋期间的每条数量变更写入内容变更流水；重新封袋仍须双人，记录 `RESEAL`。
- 处置单位已签收（`SIGNED_OFF`）的袋不得再拆袋或交接。

### 4. 冷藏全程冷链，沿袋号可追溯
- 冷藏袋每次交接必须登记交出温度（2–8℃，超区间 `409` 拒绝）、冷藏周转箱等冷链设备、冷链库位。
- 接收人扫码（本地模拟）时复测温度，超区间只能拒收；非指定接收人签收返回 `403`。
- `GET /api/bags/{bagNo}/trace` 返回封袋信息、封/拆袋双人流水、内容变更、**完整交接链**、
  当前位置与持有人。

### 5. 居民只能查询本人凭证
- 必须同时提供 **凭证编号 + 6 位查询码**，二者任一不匹配统一返回 `403`
  （不暴露凭证编号是否存在）。
- 返回内容仅含本人交回数量与处置签收进度，**刻意剔除**工作人员、工号、库位、交接链、
  温度等内部资料；居民之间互不可见。

### 6. 本地模拟扫码 / 通知
- 预约成功、差异确认、处置完成等向居民写入「本地模拟短信」；发起交接向接收人写入
  「待扫码签收」提醒。均落库于 `notification` 表，前端可见，无任何外部调用。

## 交付前可验证结果

`./run.sh test`（QuarkusTest + REST-Assured，12 个用例）实际断言：

| 验证点 | 用例 | 结果 |
| --- | --- | --- |
| 封袋后无法随意改动 | 对已封袋追加 → `409`；装袋数量超可用实收 → `409` | ✅ |
| 拆袋需双人确认 | 同一人 → `409`、缺复核人 → `400`、两人成功且 `OPEN/RESEAL` 留痕、变更前后数量可查 | ✅ |
| 危险药品双人核对 | 无复核人 → `400`；双人成功并记录复核人 | ✅ |
| 冷藏交接可追溯 | 缺温度 `400`、温度超区间 `409`、非冷链库位 `400`；合规交接温度/设备/库位/人员沿袋号完整可查 | ✅ |
| 非接收人不能签收 | 指定接收人之外签收 → `403`；复测超温 → `409` | ✅ |
| 处置单位签收 | 全部袋签收后预约 `COMPLETED`，袋 `SIGNED_OFF` | ✅ |
| 居民权限隔离 | 错误查询码 / 他人查询码 / 不存在凭证均 `403`；本人凭证 JSON 不含 `storageLocation`、工号、交接链、温度等内部字段 | ✅ |

## REST API 概览

| 方法 & 路径 | 说明 |
| --- | --- |
| `GET  /api/categories` | 药品类别字典（含危险/冷藏文字处理要求） |
| `GET  /api/staff` | 工作人员 |
| `POST /api/appointments` | 居民预约（生成凭证编号 + 查询码，模拟短信） |
| `GET  /api/appointments` · `GET /api/appointments/{code}` | 预约列表 / 详情（含可封袋数量） |
| `PUT  /api/appointments/{code}/receive` | 现场核对实收数量 |
| `PUT  /api/appointments/{code}/confirm-difference` | 居民确认数量差异 |
| `POST /api/bags` | 按类别封袋（危险需复核人、冷藏需温度/冷链库位） |
| `POST /api/bags/{bagNo}/entries` | 追加药品（封袋状态被 `409` 拦截） |
| `POST /api/bags/{bagNo}/open` | 双人复核拆袋 |
| `PUT  /api/bags/{bagNo}/entries` | 拆袋期间调整数量（逐条留痕） |
| `POST /api/bags/{bagNo}/reseal` | 双人复核重新封袋 |
| `GET  /api/bags/{bagNo}/trace` | 沿袋号完整追溯 |
| `POST /api/handovers` | 发起保管转交 / 送处置（冷藏强制温度+冷链设备） |
| `PUT  /api/handovers/{id}/accept` | 接收人扫码签收 / 拒收（本地模拟） |
| `POST /api/resident/receipt` | 居民凭凭证编号+查询码查本人凭证 |
| `POST /api/resident/notifications` | 居民本人通知 |
| `GET  /api/notifications?employeeNo=` | 工作人员本地模拟通知 |

## 项目结构

```
.
├── run.sh                       # 一条命令启动 / ./run.sh test 验证
├── pom.xml                      # Quarkus + Hibernate + SQLite(quarkiverse) + community-dialect
├── src/main/java/com/medreturn
│   ├── domain/                  # 枚举与药品类别（危险/冷藏文字处理要求）
│   ├── entity/                  # JPA 实体（居民/预约/明细/封袋/拆袋留痕/交接/通知）
│   ├── service/                 # 核心业务规则（封袋冻结、双人拆袋、冷链、居民权限）
│   ├── web/                     # REST 资源、异常映射、DTO
│   └── bootstrap/DataInitializer.java
├── src/main/resources/application.properties   # SQLite + SQLiteDialect
├── src/test/java/com/medreturn/WorkflowTest.java
└── web/                         # Svelte + Vite 前端（构建到 src/main/resources/META-INF/resources）
```
